How the scores are worked out, and what they miss
Difficulty (25%)
Every module gets a tier from 1 (presentation, config, docs) to 5 (money, security, identity, production infrastructure, engines and AI agents). The score is the line-weighted average tier of a developer's code, mapped so tier 1 is 0 and tier 5 is 100.
Hard-feature output (20%)
Lines added, each weighted by its tier (tier 5 counts fully, tier 1 a fifth), as a share of the top developer and cube-rooted so size has diminishing returns.
Volume (10%)
Lines of code added, cube-rooted against the top developer.
Breadth (10%)
Number of modules where the developer added 200+ lines, against the top developer.
Ownership (10%)
Modules (800+ lines in all) where the developer added the most lines, weighted by tier and square-rooted against the top developer.
Tests (10%)
Share of the developer's lines that are tests; 35% or more earns full marks.
Consistency (10%)
Distinct days with at least one commit, against the most active developer.
Commit hygiene (5%)
Share of commits titled with a ticket id or a conventional prefix such as feat: or fix:.
Feature score
30% technical depth, 25% domain risk and 20% integration surface, each rated 1–5 from reading the code; 15% size (square root of code lines against the largest feature) and 10% tests (0.8 test lines per code line earns full marks).
  • These scores measure the git record. They don't measure code quality, design, reviews, mentoring, on-call or business impact, and shouldn't be used alone to judge people.
  • Generated and data files (lockfiles, build output, JSON, CSV, Markdown, images) are left out. Infrastructure files such as Terraform, CI workflows, Dockerfiles and deploy config count in full.
  • Merges are skipped. A change that appears on several branches or in several repos counts once. Copied or ported code still counts for whoever committed it.
  • Work done outside git (cloud consoles, manual ops, design docs) isn't scored.
  • Sample report: real scores from nine Roinet repos, with developer names replaced by their rank.
  • Copies are skipped so nobody gets credit twice: vendored packages, a hierarchy UI copied between apps, a payout service seeded from AMS, and a chatbot seeded from RIA. Generated code and data tables stored as code don't count.
